ISO identifier of message originator's location (i.e. geographic location and/or desk). 

The first two bytes as per ISO 3166-1, identify only the country (e.g., JP = Japan, CN = China).

For valid values, refer to ftp.cmegroup.com/fix/coo. 

Market Regulation requires only the submission of the two first characters of tag 142–SenderLocationID for all countries with the exception of Canada. For Canada, the 5 bytes including the province code must be submitted.

Mass Order Status Request (MOSR) 

Currently, CGW customers can submit MOSR for all working orders, a particular instrument, or a product group.

With this release, the new type will be added to support retrieving order status for a particular Market Segment ID. 

  • Tag 1300-Market SegmentID will be added to the Order Mass Status Request(tag 35-MsgType=AF)  message 
  • New Value will be added to tag 585-MassStatusReqType on the Order Mass Status Request(tag 35-MsgType=AF)  message 

For MSGW, MOSR functionality will be applicable only for the given tag 1300-MarketSegmentID. 

For CGW sessions, MOSR behavior is unchanged. MOSR is supported for:

  • Instrument (tag 585-MassStatusReqType=1)
  • Product Group (tag 585-MassStatusReqType=3)
  • All working orders (tag 585-MassStatusReqType=7)
  • All working orders for a specific Market Segment (tag 585-MassStatusReqType=100) 

For MSGW sessions, MOSR functionality will retrieve status only for the given tag 1300-MarketSegmentID/tag 57-TargetSubID. 

For MSGW sessions, MOSR is supported for:

  • Instrument (tag 585-MassStatusReqType=1)
  • Product Group (tag 585-MassStatusReqType=3)
  • All working orders for a specific Market Segment (tag 585-MassStatusReqType=100)

Note -  If a MSGW session submits MOSR for all working orders(tag 585-MassStatusReqType=7), CME Globex will send a Business Level Reject with tag 58=FIX field incorrect 'Order Status for all Orders Not Available on Market Segment Session: '7' tag: 585'.
